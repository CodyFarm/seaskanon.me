# Vocab Studio 词汇库与短写作设计

日期：2026-09-10。状态：B 架构与产品流程已确认，本文件补齐实现细节。实施计划见 `../plans/2026-09-10-vocab-writing-practice.md`。

## 1. 产品目标与边界

管理员输入学习过的单词，通过每次 8–12 分钟、80–140 词的英语段落练习，把词汇应用到观点、原因、例证或让步论证中。AI 依据 IELTS 写作质量维度批改，提供针对性修改和参考段。用户决定是否调整掌握程度。

沿用管理员登录、Astro 6、Node 22 和现有主题。采用 B：Astro 组件、独立 TypeScript 客户端模块、服务端 API。现有练习册生成与笔记丰富继续可用。首版范围为手动维护词汇、自动或手动选词、出题、写作、批改、修改重交和复习时间更新。词汇库永久保存；本轮任务、草稿和批改在 sessionStorage 保存，刷新可恢复，关闭标签页后不承诺恢复，不建立作文历史库。

不引入前端框架、数据库服务或新增业务属性。首版包含从单篇笔记或当前粘贴文本提取候选词、人工审核后批量入库，并把词汇筛选器作为词库、写作平台和练习册生成器共用模块。全目录批量扫描、词汇用法历史和长期学习曲线留待独立需求。

## 2. 词汇记录

词汇记录包含四组业务信息：词形与释义、首次加入时间、最近练习时间、掌握等级。JSON 展开为七个字段：

```json
[
  {
    "word": "compulsory",
    "partOfSpeech": "adjective",
    "meaningZh": "强制的；义务的",
    "meaningEn": "required by a rule or law",
    "addedAt": "2026-09-10T08:00:00.000Z",
    "lastPracticedAt": null,
    "mastery": 2
  }
]
```

- word：1–80 字符，允许英文单词和短语；NFKC 规范化、trim、连续空白折叠，去重比较使用小写。保存原大小写以保留专有名词。同词不同词性或义项首版合并到一条记录。
- partOfSpeech：1–40 字符；界面提供 noun、verb、adjective、adverb、phrase 等建议，也允许自定义。
- meaningZh、meaningEn：分别 1–200、1–300 字符；支持手动录入，不依赖模型在线。
- addedAt：服务端首次新增时生成 UTC ISO 时间；不能通过普通编辑修改。
- lastPracticedAt：初始 null；仅在有效批改成功且用词确实出现后更新。误用也算一次练习，未使用不更新。接口失败不更新时间。
- mastery：1–5 整数，默认 1，由用户决定最终值。

不增加 id、次数、错误类型、来源、备注等持久化字段。规范化词形作为技术键；编辑可以纠正拼写，以 originalWord 定位旧记录，在同一次写入中检查新词是否重复，保留原时间。已生成的任务继续使用原快照；批改完成时若词已改名或删除，跳过该词的状态更新并提示。

| 等级 | 页面名称 | 自评含义 |
| --- | --- | --- |
| 1 | 初识 | 刚加入，看到后仍不熟悉意思 |
| 2 | 认得 | 能认出意思，写作时难以主动想起 |
| 3 | 能用 | 借助提示能造句，搭配偶有问题 |
| 4 | 熟练 | 通常能准确、自然地应用 |
| 5 | 稳定 | 多次在不同语境下主动、准确使用 |

一次正确使用不足以证明长期掌握。AI 每轮建议最多升降一级；未使用保持原级；不从单次表现建议升至 5。用户可在编辑页自行选择任意等级。

## 3. 文件存储与部署

文件名为 vocab-library.json，存储目录由服务端 VOCAB_DATA_DIR 配置；本地默认项目 `.local/vocab/`，生产使用持久卷 `/data/vocab`。生产缺少显式配置或目录不可写时，新词库 API 返回配置错误，不能静默写到会随部署删除的目录。已有博客代码使用 `/data/blog` 的模式可以参考，但词库不放进博客目录或 public，不参与文章扫描。

真实词库和临时文件加入 gitignore，不提交到 Git，不放在 src/data，也不由构建产物初始化覆盖。只在目标文件确实不存在时创建空数组；JSON 损坏、权限错误必须报错，不能按空库处理。部署时先挂载持久卷、配置路径，再验证写入后重启能读回。

首版支持单个 Node 服务进程。进程内共用写队列，整个“重读、校验、修改、写临时文件、rename”都在队列中执行。临时文件与目标同目录、文件名唯一，失败保留旧文件并清理本次临时文件。原子替换防止半截文件，写队列防止并发丢失更新。多进程共享文件不在首版支持范围。

列表返回词库内容摘要 revision。人工新增、编辑、删除携带 expectedRevision；在写队列内比较，不一致返回 409，让用户刷新并保留未保存输入。revision 由内容计算，不额外存为词汇字段。练习时间写入使用 max(旧时间, 本次批改完成时间)，不会覆盖用户编辑的释义或等级。

## 4. 页面设计

Vocab Studio 四个页签：生成练习册、丰富笔记、词汇库、短写作。笔记侧栏只在前两个页签显示，新增功能获得完整宽度。四个页签共享同一个“词汇筛选器”和“确认清单”组件，不允许各页签各自实现一套筛选规则。

词汇库顶部展示总词数、1–2 级词数、最近 7 天练习过的词数。最后一项是词数，不是练习次数。支持关键词搜索、等级、加入时间和最近练习时间筛选，以及词形、等级、加入时间、最近练习时间排序。筛选后的条数与全库统计分开显示。

桌面使用表格，移动端显示词汇卡片或横向滚动表格。等级同时使用数字、文字和颜色。新增/编辑抽屉包含四个文本字段和等级分段控件；时间只读。抽屉显示字段级错误，支持键盘、焦点归还和 Escape 关闭，存在未保存输入时提示。删除确认显示具体词形。

写作配置默认自动主题、观点段、5 个目标词、均衡组合；可选原因、例证、让步段，目标数量 3–6，组合预设为均衡/巩固优先/新词优先。写作使用共享筛选器产生候选，再打开读取确认清单；用户确认后才生成任务。支持从词库手动选择 3–6 个词，手选结果也必须经过确认清单。配置不是词汇业务字段。

任务卡展示英文题目、中文任务说明、段落类型、2–3 条结构提示、目标词及词义、预计用时和字数范围。任务卡只在读取确认清单提交后生成；开始写作前不展示完整范文。编辑区使用 textarea，显示词数与词形出现提示；提示不代表用法正确，也不强制用全目标词。

结果页先展示两个最优先修改点和目标词用法，再展示四维反馈、逐句意见、保留原意的修改稿、单独的 AI 参考段。提供“修改后重交”“逐词采纳等级建议”“下一题”。查看示例后修改仍可批改，但界面标记为参考后的修改稿，不作为独立掌握证据。

## 5. 选词规则

新词：最近 14 天加入；低掌握：1–2 级；熟词：4–5 级。角色按顺序分配且同一词只出现一次。

| 组合 | 新词名额 | 低掌握名额 | 熟词名额 |
| --- | --- | --- | --- |
| 均衡 | 1 | n-2 | 1 |
| 巩固优先 | 1 | n-1 | 0 |
| 新词优先 | min(2, n-1) | 其余 | 0 |

先选新词、再选低掌握、再选熟词；新词池按加入时间倒序，其余池按未练习优先、距上次练习最久优先、等级升序、规范化词形排序。每一池移除已选词；任何池不足均从全库尚未选择的词按复习优先顺序补足。少于 3 条时阻止出题并提示补充词汇；总量不足 n 但不少于 3 时使用实际数量并提示。规则服务端确定，AI 负责主题与自然语境，不自行替换词汇。

词汇主题不兼容时，模型返回 `{ compatible: false, reason: string }`，API 将其映射为 incompatible 错误；不输出牵强题目。界面显示冲突原因，并允许更换目标词或主题后重试。默认任务要求尽量自然使用 3–5 个目标词，不要求硬塞全部。

## 6. 模块与接口

新增组件放在 src/components/vocab/，客户端脚本放在 src/scripts/vocab/；共享类型、词库规则、存储、选词、LLM 与写作契约放在 src/lib/vocab/。只抽取现有 generate.ts 的 LLM 适配逻辑供复用，保留原接口响应和默认生成参数；新写作请求独立设置超时和输出预算。

所有新 API 使用现有 isAuthenticated，并对写请求验证同源 Origin，使用 application/json。错误格式 `{ error: { code, message } }`；不返回密钥、原始上游响应或服务器路径。

| 方法与路径 | 请求 | 响应与行为 |
| --- | --- | --- |
| GET /api/vocab/library | 无；个人词库先全量返回、浏览器筛选 | `{ entries, revision }`，no-store |
| POST /api/vocab/library | `{ entry: 可编辑字段, expectedRevision }` | 201，`{ entry, revision }` |
| PATCH /api/vocab/library | `{ originalWord, patch: 可编辑字段, expectedRevision }` | `{ entry, revision }`；冲突 409 |
| DELETE /api/vocab/library | `{ word, expectedRevision }` | `{ revision }`；不存在 404 |
| POST /api/vocab/writing/task | `{ topic, paragraphType, targetCount, mix, selectedWords? }` | `{ task }` 或 422 incompatible |
| POST /api/vocab/writing/grade | `{ task, text, submissionId, referenceViewed }` | `{ feedback, practice: { updated, skipped, saved, retryToken? } }` |
| POST /api/vocab/library/practice | `{ retryToken }` | 只重试时间保存，不再调用模型 |

新增字段全量校验，patch 只接受白名单，addedAt/lastPracticedAt 等未知字段返回 400。JSON body 上限 64 KiB；写作文本 2,000 字符；topic 120 字符；枚举、数量和字段长度均由服务端校验。异常状态包括 401 认证、400 输入、404 不存在、409 冲突、422 题目不兼容、502 模型输出、504 超时、503 存储不可用。

task 包含 taskId、createdAt、topic、paragraphType、instruction、structureHints、targetWords 完整记录快照和固定 wordLimit `{ min:80, max:140 }`。ID、时间、词汇快照和字数范围由服务端产生，LLM 只产出题目文本、说明和结构提示。前端回传的任务需要完整校验；当前系统是管理员自练，不把分数或任务内容用于第三方成绩认证。

practice 重试令牌由服务端 HMAC 签名，携带实际出现的目标词、服务端批改时间，24 小时有效。用同一服务器认证密钥配合独立用途前缀签名；不复制 cookie 或向客户端暴露密钥。重复保存相同时间是幂等操作，不能反复推进复习时间。批改成功但文件写入失败仍返回反馈与可重试状态。

## 7. 批改契约与质量要求

```json
{
  "overallComment": "观点明确，可补充因果链。",
  "priorities": ["说明这一措施如何改变行为", "修正动词与介词搭配"],
  "scores": {
    "taskResponse": { "band": null, "comment": "..." },
    "coherence": { "band": 6.5, "comment": "..." },
    "lexicalResource": { "band": 6.0, "comment": "..." },
    "grammar": { "band": 6.0, "comment": "..." }
  },
  "targetWordUsage": [
    { "word": "compulsory", "status": "used_correctly", "evidence": "原文中的准确片段", "comment": "..." }
  ],
  "sentenceFeedback": [
    { "original": "原文句子", "issue": "...", "suggestion": "..." }
  ],
  "improvedParagraph": "保留原意并修正问题的英文段落",
  "referenceParagraph": "针对相同题目独立生成的英文参考段",
  "masterySuggestions": [
    { "word": "compulsory", "suggestedMastery": 3, "reason": "..." }
  ]
}
```

四维使用 IELTS Task Response、Coherence and Cohesion、Lexical Resource、Grammatical Range and Accuracy。单段无法评价完整作文的任务回应或整体结构，所以 band 允许 null，证据不足时不评分；禁止合成“雅思总分”。非 null 为 0–9、0.5 步长，并标注“段落练习参考”。参考段向 Band 7–8 的清晰、准确、自然表达靠拢，不以罕见词数量评价质量，不声称来自官方范文。

词汇状态限定 used_correctly、used_with_issue、not_used。正确变形可以认可，派生词或同义词替代不自动算作目标词命中。出现状态须附精确原文片段；服务端校验片段实际存在，无法验证返回输出错误，不更新时间。前端仅做词边界、大小写不敏感的词形检索，不把 art 匹配到 part，最终语义判断留给 AI。

所有目标词各返回一次，无多余词。逐句反馈 original 必须存在于提交原文。参考段和修改稿建议 80–140 词；句子反馈优先 3–6 处有实质影响的问题。空白禁止提交；少于 50 或大于 180 词提示后可继续，超过 2,000 字符服务端拒绝。

系统提示与用户作文分开传入；作文中的指令作为待批改文本。接受纯 JSON 或单一外层代码围栏，随后执行运行时校验；不使用 eval、不展示未清洗 HTML。无效输出不写词库。默认不自动重试付费请求，按钮可手动重试。为新接口提供 60 秒超时。

用户修改后重交生成新的 submissionId。编辑时使旧批改界面失效，返回结果仅关联提交时的原文快照；新题目生成不能让旧请求覆盖当前题目。等级采纳从词库刷新当前记录，使用 revision 防止覆盖另一标签页的人工修改。

## 8. 状态与恢复

状态为 configuring → generating → writing → grading → reviewed；错误回到保留输入的前一状态。时间保存失败属于 reviewed 内的单独错误，不能迫使用户再次付费批改。词形出现提示不改变任何服务器数据。

sessionStorage 存储本轮 task、draft、feedback、submissionId、referenceViewed 和待重试时间令牌。输入防抖保存；刷新恢复；主动退出清除；认证过期保留本标签页草稿，重新登录恢复。存储不可用时继续内存编辑并提示无法恢复。显示“本标签页已保存”，不暗示跨设备永久保存。

## 9. 实施验收

1. 真实数据不进 public、文章列表或 Git；配置持久目录后重启仍能读取，部署初始化不覆盖旧文件。
2. 新增、改拼写、重复词、未知字段、非法等级、日期保护、跨标签页冲突有可验证行为；损坏文件不被覆盖；并发写入不会丢词。
3. 三种选词比例在新词与低掌握词重叠、空池、少词情况下无重复且名额符合规则。
4. 出题失败、无效批改、超时不改词汇时间或等级；用错但确实使用的词更新时间，未用不更新。
5. 提交后丢连接或文件保存失败，保留原文与可用结果；时间重试不重复调用模型。
6. 错误原文证据、多余目标词、不合法分数、非法 JSON 都被拒绝；非正式评分标识一直可见。
7. 刷新恢复本轮，修改重交有明确版本；管理员退出清理本轮；移动端和键盘可以完成编辑。
8. 现有生成练习册和丰富笔记流程回归通过。实现前后运行 pnpm build；函数与接口用离线模型 stub 验证，真模型调用单独记录是否完成。
9. 从笔记或文本提取候选词不会写库；取消审核、模型失败不会改变词库。只有确认勾选项后才批量写入，重复词不新增，已有词时间与等级不被覆盖。
10. 审核期间修改源文本或词库后，能识别过期候选或 revision 冲突；批量请求失败保留审核内容，重试不重复新增。

文档阶段不修改应用代码，也不把文档检查称为构建或功能验证。

## 10. 笔记候选词提取与审核入库

补充日期：2026-09-11。入库来源新增现有 Vocab Studio 功能的笔记与文本；正式词汇记录仍只有第 2 节定义的七个字段。

### 入口与提取范围

- 选择已有词汇笔记后，显示“提取到词汇库”。
- 粘贴文本分析后，提供同一入口；不以模型连接检查成功代替候选词提取。
- 生成练习册后，优先提取源笔记或源粘贴文本，避免把题目干扰项、答案和说明重复当作学习词。
- 丰富笔记或保存当前笔记内容后，允许从用户当前编辑版本提取，明确显示“当前预览”或“已保存笔记”作为来源。
- 不新增通用 Markdown 编辑器；以上入口接入现有选择、生成、预览和保存流程。

默认只提取明确的词汇条目；“同时扫描正文和例句”默认关闭，可由用户开启。普通散文无明确条目时，返回空候选与切换扫描范围的提示，不擅自扩大范围。条目模式优先复用 vocab-parser.ts；模型补全词性及英文释义，不新增解析列表以外的词形。扫描模式可提取正文中的实用单词与短语，每个候选附来源片段，片段必须确实存在于源文本。复用解析器时覆盖编号条目与子条目，斜杠列出的词形变体拆开并交用户确认。

仅在用户点击提取时调用模型，避免每次生成都额外花费。当前生成接口返回 Markdown，首版不强制更改其响应；候选抽取使用独立接口，可复用已有解析结果。同一文本快照与范围的候选在当前会话复用，修改文本或切换范围后标为过期，再提取才替换。

### 审核清单

流程：选定来源 → 提取 → 审核 → 确认加入 → 显示结果。候选状态只存在当前标签页，不写入词汇文件。

每行显示复选框、单词/短语、词性、中文释义、英文释义、掌握等级和“新词/已存在”标记，展开可查看来源片段。字段可编辑，新增等级默认为 1。默认不勾选任何行；可点击“勾选全部新词”，最终按钮显示“确认加入 N 个词”。空选禁用提交。重名检测随词形修改重新运行。

已有词默认跳过；可显式选择“更新释义”，展示新旧字段差异，再次随最终确认提交。该操作只更新词性和双语释义，保留词形、addedAt、lastPracticedAt 和 mastery。需要调整已有词等级时转到词汇库编辑，不通过候选批量覆盖。

新增词 addedAt 为审核确认写入时的服务端时间，lastPracticedAt 为 null；笔记中出现不算写作练习。提取、保存笔记、关闭审核均不会自动入库。笔记保存与词库导入是两个独立操作，入库失败不撤销已保存笔记，也不把“笔记保存成功”显示为“入库成功”。

### API 与批量语义

`POST /api/vocab/library/candidates` 请求 `{ text, scope: "entries" | "expanded" }`。text 为明确选定的源快照，限制 20,000 字符；返回 `{ sourceHash, scope, candidates, revision }`。每个候选为 `{ entry: EditableEntry, evidence: string, existing: boolean }`，最多 100 项，规范化去重；existing 由服务端查库计算，不信任模型。正文扫描直接返回原文词形，不自动进行可能无法核验的词根转换。该接口只读词库、不写文件，复用认证、超时、JSON 校验和同源约束。

`POST /api/vocab/library/import` 请求 `{ expectedRevision, items }`；items 最多 100 项，元素为 `{ action: "create" | "updateMeanings", entry: EditableEntry }`。create 仅接受新词；updateMeanings 仅接受已有词，忽略候选等级但不改已有等级。重复操作 key、非法字段、超量和空数组均返回 400。

整批在同一 store 写队列内校验 revision、查重并原子写入，不采用逐词部分成功。成功返回 `{ created: string[], updated: string[], revision }`；任何字段错误或文件写入失败整批不落库，审核输入保留。revision 过期返回 409，刷新已有词状态后由用户重新确认，不能自动改成覆盖。

若响应丢失而写入可能已成功，客户端先 GET 词库核对：已经存在的新词标记为“已存在，跳过”，不自动重发为更新。剩余项由用户再次确认。此规则避免重试覆盖时间或把新词误判为二次学习。

来源片段、sourceHash、existing、action 均为会话或请求元数据，不加入正式词汇记录。sessionStorage 对候选保存与草稿采用同样的退出清理、过期识别和不可用降级规则。

## 11. 写作平台学习体验

### 11.1 一次练习的节奏

平台把一轮控制在三个阶段：准备 2 分钟、写作 6–8 分钟、反馈 3–5 分钟。准备阶段只给题目、段落目标和词汇提示；不展示完整参考段，也不先给可直接复制的论点。写作阶段只保留必要工具，避免用户在题目、词库表格和 AI 对话之间来回切换。反馈阶段先给两个最值得修改的点，再展开细节，保证时间有限时仍能完成复盘。

每轮任务只训练一个段落功能。观点段要求立场加理由，原因段要求因果链，例证段要求具体情境与结果，让步段要求承认限制后回到主张。题目卡明确写出“本轮成功标准”，例如“明确回答问题、解释一个原因、给出一个具体例子”，不把 IELTS 四项维度变成用户需要同时完成的清单。

### 11.2 编辑器辅助的边界

编辑器提供词数、目标词出现提示、撤销/重做、清空和保存草稿。目标词提示分为“未出现”和“已出现”，不显示自动替换建议；用户点击词汇时可以查看词性与中英文释义，但不会把词直接插入正文。首版不提供实时语法纠错、自动续写、句子翻译或一键润色，以免用户在提交前失去独立回忆和组织能力。

在用户主动点击“给一个提示”后，AI 只能返回一个与段落目标相关的中文问题或结构提醒，例如“这个原因如何影响学生的选择？”；每轮最多三次，提示内容计入当前 session，不改变题目和目标词。提示不生成英文句子，不改变掌握等级，也不进入最终批改的参考段上下文。

### 11.3 反馈阅读顺序

反馈页采用由行动到解释的顺序：

1. “先改这两处”：每项包含问题、原因和一个可执行动作。
2. “目标词使用”：逐词显示正确、使用有问题或未使用，并引用原文证据。
3. “四项参考维度”：分数可为空，配一条基于段落证据的说明。
4. “逐句反馈”：默认折叠，按严重程度排序，最多先展开三处。
5. “我的修改稿”：保留原意的示例，标出关键改动。
6. “风格参考段”：独立生成，标注为 AI 示例，默认折叠。

修改稿和参考段必须视觉区分。参考段不能成为用户提交的替代答案；查看参考段后，页面显示“已查看参考”，用户再次提交时将该标记传给服务端，但不因此惩罚评分，只在掌握建议中降低证据强度。

### 11.4 复写循环

反馈后主操作是“自己改一遍”，而不是“复制改进稿”。点击后保留原文、在编辑器中生成可编辑副本，并在侧栏显示两个优先问题；改写稿初始为空，不自动填入 AI 版本。用户可展开 AI 修改稿逐句对照，再自行输入。第二次提交沿用同一 taskId 但使用新的 submissionId，结果页同时显示“初稿/复写稿”标签；两次结果只在当前 session 保留，不写入文件。practice 时间只在用户点击“完成本轮”时保存一次，避免同一轮重复提交造成虚假的练习记录。

### 11.5 词汇掌握建议

AI 建议依据目标词的使用状态、语境准确性和用户是否查看参考段，最多相对当前等级调整一级。正确且自然使用可建议保持或上调一级；使用有问题可建议保持或下调一级；未使用不改变建议。页面逐词显示“当前等级 → 建议等级”和理由，默认全不采纳，支持逐项采纳、全部采纳和跳过。采纳前重新读取词库 revision，冲突时让用户刷新后再选，不覆盖其他标签页的人工编辑。

### 11.6 无障碍、隐私与响应式

所有状态变化写入 `aria-live="polite"`，生成和批改期间按钮显示忙碌状态并保留可取消操作。颜色不是等级和词汇状态的唯一信息；表格、抽屉、折叠区和错误提示有可见焦点与键盘路径。移动端先显示题目和编辑器，目标词改为可横向滚动的芯片；反馈各部分按单列顺序展开，避免在 375px 宽度下出现双栏挤压。

作文原文只发送到已配置的 LLM provider，不进入访问日志、词库文件或博客内容。页面不展示 provider 名称和 API key。提交前显示“内容将发送给当前模型服务用于批改”的简短提示；管理员可在设置中关闭 AI 参考段生成以减少原文暴露和费用，关闭时批改仍返回维度反馈、词汇使用和修改建议。

## 12. 可观测性与费用控制

服务端记录请求类型、耗时、HTTP 状态、解析结果和目标词数量，不记录作文原文、提示词全文或模型返回全文。每次 task 和 grade 使用随机 requestId 关联日志；客户端只接收 requestId 供失败反馈使用。单轮最多一次出题、两次批改（初稿与复写）和三次提示；超出限制返回清晰提示，不自动触发模型调用。

任务生成优先从本地选词和规则模板构造上下文，批改只把当前题目快照、目标词必要字段和用户原文发给模型。参考段可以通过配置关闭；关闭后服务端要求模型返回空字符串而非自行补写。达到输入长度、模型超时或上游限流时，界面保留草稿并提供“稍后重试”，不重复扣费式自动重试。

## 13. 设计验收补充

11. 题目一次只训练一个段落功能，准备阶段没有完整范文；编辑器不主动生成英文内容，提示次数最多三次。
12. 反馈页按“优先修改点 → 目标词 → 维度 → 逐句 → 修改稿 → 参考段”顺序呈现，参考段默认折叠且明确标注 AI 示例。
13. 复写不会自动填入改进稿；同一轮重复批改不重复更新时间，只有完成本轮才写入 practice 时间。
14. 评分、词汇建议和参考段可以独立失败；参考段关闭或失败不会阻止其他反馈显示。
15. 练习原文不写入日志、词库或博客；请求数量和参考段开关按服务端限制执行。
